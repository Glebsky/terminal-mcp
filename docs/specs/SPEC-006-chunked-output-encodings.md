# SPEC-006 · Неполное и битое чтение: обрезки, страницы, кодировки

- **Статус:** Реализовано (ожидает ручной проверки в собранном приложении, T11). 2026-11-20: AC1–AC5 выполнены, разовый фазз 4000 прогонов без ошибок
- **Дата:** 2026-11-20
- **Область:** сервер (`src/`), десктоп (`desktop/src/main/`)
- **Связано:** SPEC-005 FR-5 (`file_read`), `docs/audit/2026-11-20-stability-races.md` («Лог в десктопе режет строки»)

## 1. Контекст

После починки `file_read` проверили остальные места, где данные приходят кусками или режутся по лимиту (зонд на изолированном сервере, 2026-11-20):

1. `terminal_execute` с `shell: "cmd"`: встроенные команды пишут в OEM-кодировке (cp866), хотя перед командой стоит `chcp 65001`: `echo привет` → «�ਢ��», заголовки `dir` и `vol` нечитаемы. cmd читает кодовую страницу один раз на строку, вложенный `cmd /c` после `chcp` печатает UTF-8.
2. Там же двойные кавычки ломаются: `echo "a b"` → `\"a b\"`. Node экранирует кавычки по правилам MSVCRT, cmd их не понимает, и `dir "C:\Program Files"` не работает.
3. Обрезка вывода `terminal_execute` по `MAX_OUTPUT_BYTES` режет символ: при лимите 11 байт «привет» → «приве�».
4. `file_search` молча отвечает `matches: 0, truncated: false`, когда совпадение стоит после 4000-го символа строки, файл больше 2 МБ или в cp1251. Фрагмент строки в результате может кончаться половиной эмодзи.
5. `browser_get_content` сравнивает лимит в байтах с длиной строки в символах, режет `slice` без учёта суррогатных пар и не даёт дочитать остаток.
6. `file_list` после `max_entries` отвечает `truncated: true` без продолжения.
7. Лог десктопа декодирует каждый кусок stdout/stderr сервера отдельно и режет на строки без остатка: строки `[AUDIT]` рвутся, кириллица на стыке становится «�».

Уже в порядке и не меняется: чтение вывода cloudflared/tuna (`src/tunnel/cli.ts`), склейка многочанкового вывода `terminal_execute`, `file_read` после SPEC-005, base64.

## 2. Требования

### FR-1 · terminal_execute в cmd
- FR-1.1 Встроенные команды cmd и программы, уважающие кодовую страницу консоли, отдают UTF-8: `echo привет` → «привет», имена файлов в `dir` читаемы.
- FR-1.2 Текст команды доходит до cmd буквально: кавычки, `&`, `|`, `>`, `%`, `^`, `!` работают так же, как в `cmd /c` из консоли.
- FR-1.3 Код выхода равен коду выхода команды (`exit /b 3` → 3).

### FR-2 · Обрезка вывода команды
- FR-2.1 Если stdout или stderr упёрся в `MAX_OUTPUT_BYTES`, недописанный последний символ отбрасывается, «�» в конце нет.
- FR-2.2 Описание инструмента говорит, что длинный вывод надо перенаправить в файл и читать через `file_read`.

### FR-3 · file_search без молчаливых пропусков
- FR-3.1 Строка ищется целиком: длиннее 4000 символов перекрывающимися окнами 4000 / нахлёст 1000 (защита от долгого regex остаётся). Совпадение длиннее 1000 символов на такой строке может не найтись. `^` и `$` не срабатывают ложно на границах окон.
- FR-3.2 Ищутся файлы до `MAX_FILE_BYTES` (было 2 МБ). Большие файлы, нечитаемые файлы и папки попадают в `skipped: [{ path, reason }]` (до 50) и `skipped_total`. Бинарные файлы пропускаются молча, как раньше.
- FR-3.3 Текст не в UTF-8 декодируется ANSI-кодировкой системы (например windows-1251), UTF-16 с BOM (вывод `>` из Windows PowerShell 5.1) читается как UTF-16. У таких совпадений есть поле `encoding`.
- FR-3.4 `snippet` берётся вокруг совпадения (до 500 символов), остаётся дословной подстрокой файла и не режет суррогатные пары; новое поле `column` (с 1, в символах UTF-16).

### FR-4 · browser_get_content по страницам
- FR-4.1 Лимит `MAX_OUTPUT_BYTES` считается в байтах UTF-8 и режет по границе символа.
- FR-4.2 Новые параметры `offset` и `length` (в символах UTF-16, как в JavaScript); в ответе `offset`, `length`, `total_length`, а пока `truncated: true`, ещё `next_offset`. Границы не режут суррогатные пары. Если страница меняется между вызовами, куски не согласованы.

### FR-5 · file_list по страницам
- FR-5.1 Новый параметр `offset` (сколько записей пропустить); при `truncated: true` в ответе `next_offset`. Страницы согласованы, пока папка не меняется.

### FR-6 · Лог десктопа
- FR-6.1 stdout и stderr сервера декодируются потоково (StringDecoder), дальше идут только целые строки; хвост без перевода строки ждёт следующего куска и выдаётся при закрытии потока или при длине больше 64 КБ.
- FR-6.2 Строки stderr из одного куска остаются одной записью лога, как раньше (стеки не рассыпаются).

### Не входит в задачу
- Программы, которые пишут в OEM-кодировке независимо от кодовой страницы консоли: их вывод не перекодируется.
- `file_read` и `file_replace` для файлов не в UTF-8: по-прежнему base64 и отказ (SPEC-005).

## 3. Дизайн

- `src/utils/text.ts` (новый): `isUtf8Continuation`, `utf8SequenceLength` (переезжают из `filesystem.ts`), `trimIncompleteUtf8`, `truncateUtf8`, `alignCodePoint`, `pageText`, `snippetAround`, `decodeText` + `legacyDecoder` (ANSI-кодировка из `HKLM\...\Nls\CodePage\ACP`, один раз лениво).
- `src/tools/command.ts`: cmd запускается как `cmd.exe /d /v:on /c chcp 65001 >nul & cmd.exe /d /s /c "!MCP_TERMINAL_COMMAND!"` с `windowsVerbatimArguments`, сама команда едет в переменной окружения. Отложенное раскрытие подставляет её после разбора строки, поэтому внешний cmd не трогает её кавычки и операторы; внутренний cmd стартует уже с кодовой страницей 65001, а `/s` снимает только нашу внешнюю пару кавычек. При обрезке вывода `trimIncompleteUtf8`.
- `src/tools/filesystem.ts`: `searchFiles` через `decodeText`, `findInLine` (окна + защита `^`/`$`), `skipped`; `listFiles(…, offset)`.
- `src/tools/browser.ts`: `getContent` через `pageText`.
- `desktop/src/main/line-buffer.ts` (новый, без импорта electron, чтобы тестировать из node) и `server-manager.ts`: `setEncoding("utf8")` + `createLineBuffer`.

## 5. Критерии приёмки

- AC1. Стенд K: `echo привет` → «привет»; `echo "a b"` → `"a b"`; `dir /b` папки с файлом «отчёт.txt» показывает имя читаемо; `echo a & echo b`, `echo x | findstr x`, `echo 100%`, `echo hi!`, `echo a^&b`, `for %f in (x y) do @echo %f` дают то же, что `cmd /c` в консоли; `exit /b 3` → `exitCode: 3`; при `MAX_OUTPUT_BYTES=11` «привет» → «приве» без «�».
- AC2. Стенд F: находится совпадение после 4000-го символа, в файле 2.5 МБ, в cp1251 (`encoding: "windows-1251"`) и в UTF-16LE с BOM; файл больше `MAX_FILE_BYTES` попадает в `skipped`; `^NEEDLE` не срабатывает на границе окна; snippet с эмодзи без одинокого суррогата.
- AC3. Стенд L: 520 файлов страницами по 200 через `next_offset` дают 520 разных имён без повторов.
- AC4. Фазз: `pageText` склеивает случайный текст с эмодзи и кириллицей без потерь и одиноких суррогатов при любых `length` и лимитах байт; `truncateUtf8` не даёт «�»; `createLineBuffer` при случайной нарезке байтов выдаёт ровно исходные строки.
- AC5. Регресс: стенд A, B, C, D, G, I, S, X и `tests/*` как после SPEC-005.
