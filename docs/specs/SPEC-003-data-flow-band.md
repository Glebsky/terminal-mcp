# SPEC-003 · Полоса «Поток данных» в мониторе подключений

- **Статус:** Реализовано (ожидает ручной проверки в Electron, T9)
- **Дата:** 2026-11-19
- **Область:** десктопное приложение (`desktop/src/renderer`)
- **Заменяет:** SPEC-001, FR-2 (частицы потока данных)

## 1. Контекст и проблема

Поток данных показывался отдельными DOM-частицами (до 120 узлов, подпись «≈ N на частицу»). Объём трафика читался плохо: поток мелких запросов и одна большая передача выглядели почти одинаково, а сама труба не соответствовала сине-фиолетовому стилю приложения. Нужна одна главная полоса, ширина которой отражает объём, с плавными переходами и затуханием при остановке передачи.

## 2. Требования

### FR-1 · Полоса
- FR-1.1 Главный элемент: одна полоса с градиентом от голубого (клиент, слева) через синий и индиго к фиолетовому (сервер, справа): `#3cc8ff → #4a92ff → #6a6dff → #b26bff`.
- FR-1.2 Толщина полосы следует за объёмом полезной нагрузки за последнюю секунду по логарифмической шкале: любой трафик даёт минимум видимую нить (12 % высоты), полная ширина около 4 МиБ/с.
- FR-1.3 Входящий трафик идёт волной слева направо, исходящий справа налево. Волна пересекает трубу примерно за 3,4 с, слегка ослабевает по пути и мягко гаснет у дальнего узла.
- FR-1.4 Поверх полосы летят светлые «пакеты», их частота растёт с объёмом. Уже вылетевший пакет всегда долетает до конца.
- FR-1.5 Без трафика остаётся тихая «несущая»: тонкая дышащая нить. При выключенном сервере она приглушена, при запуске плавно «просыпается».

### FR-2 · Плавность
- FR-2.1 Снимок мониторинга (раз в секунду) только задаёт цель. Огибающая нарастает с постоянной времени 0,3 с и спадает с 0,95 с, скачков нет.
- FR-2.2 Если трафик прекратился или снимки не приходят дольше 1,8 с, полоса плавно затухает до несущей.
- FR-2.3 Подпись «Ожидание трафика» (или «Запустите сервер…») и индикатор в заголовке секции переключаются кроссфейдом, когда огибающая опустилась ниже 5 % (с задержкой 0,4 с).
- FR-2.4 Числа байт/с в карточках, легенде и заголовке плавно досчитываются к новому значению (ease-out, 650 мс), цифры моноширинные (`tabular-nums`).
- FR-2.5 Узлы-стрелки по краям светятся в такт огибающей своего направления.
- FR-2.6 Секция появляется с мягким fade-in, элементы легенды — с коротким всплытием.

### FR-3 · Доступность и производительность
- FR-3.1 При выключенных анимациях интерфейса или системном Reduced Motion полоса рисуется статично по текущему снимку, без цикла анимации.
- FR-3.2 Отрисовка на canvas с учётом devicePixelRatio (до 3×). В тихом состоянии 30 кадров/с, при трафике 60; не более 56 пакетов. React не перерисовывается на каждом кадре; свечение узлов передаётся CSS-переменными только при изменении.
- FR-3.3 Полоса имеет `role="img"` и подпись с текущими скоростями.
- FR-3.4 В светлой теме секция следует светлой поверхности, сама труба остаётся тёмным «экраном», чтобы свечение читалось.

### Не входит в задачу
- Изменения сбора метрик на сервере и формата `MonitorSnapshot`.
- Пользовательская настройка шкалы (полная ширина задаётся константой).

## 3. Дизайн

- `components/flow/flowRibbonEngine.ts`: движок без React. На каждое направление один `Lane`: огибающая attack/release и кольцевой буфер истории (шаг 2 px), который переносит огибающую вдоль трубы. Кадр: столбики с шагом 4 px (три уровня яркости, проход свечения и чёткий проход), маска затухания кончиков, размытое «тело» полосы (рисуется в 1/5 разрешения и масштабируется), пакеты, маска краёв под узлами.
- Текстура столбиков: гладкий value noise. Мелкий масштаб дрейфует по направлению потока, крупные кластеры едут со скоростью волны, контраст растянут smoothstep, чтобы у волны были пики и провалы.
- `components/flow/FlowRibbon.tsx`: canvas, узлы и подпись ожидания; ResizeObserver, передача снимков в движок, класс `is-idle`.
- `components/flow/EasedValue.tsx`: плавный счётчик, рендерит только текст и наследует стили обёртки.
- `Monitor.tsx`: частицы и их палитры удалены, секция собирается из `FlowRibbon` и `EasedValue`.
- CSS (`styles/liquid-glass.css`): `.pipe-section`, `.flow-pipe` (96 px), `.pipe-node` со свечением через `--flow-in` / `--flow-out`, `.pipe-idle`, `.flow-live-dot`, анимация появления легенды; старые правила частиц и `.pipe-grid` удалены. Светлая тема: `styles/settings.css`.
- i18n: ключ `monitor.perParticle` заменён на `monitor.throughput` («{size}/с суммарно · последняя секунда») в en / uk / ru.
- Стенд: `desktop/preview/flow.html` (в сборку не входит). Сценарии `idle`, `trickle`, `steady`, `bursts`, `heavy`, `upload`, `offline` и режим без анимаций; `window.probe()` и `window.record(scenario, ms)` для замеров. Запуск: `npx vite --port 5174`, затем `http://localhost:5174/preview/flow.html#heavy`.

Параметры (константы в `flowRibbonEngine.ts`):

| Константа | Значение | Смысл |
|---|---|---|
| `FULL_SCALE_BYTES` | 4 МиБ/с | полная ширина полосы |
| `MIN_LEVEL` | 0.12 | минимальная толщина при любом трафике |
| `CROSSING_SECONDS` | 3.4 | время прохода волны через трубу |
| `ATTACK_SECONDS` / `RELEASE_SECONDS` | 0.3 / 0.95 | нарастание / спад огибающей |
| `STALE_MS` | 1800 | после этого поток считается остановленным |
| `IDLE_PEAK` / `IDLE_DELAY_MS` | 0.05 / 400 | порог и задержка состояния ожидания |
| `MAX_PACKETS` | 56 | лимит пакетов в полёте |

## 5. Критерии приёмки

- При малом трафике полоса узкая, при большом широкая; переходы без скачков.
- Входящий трафик визуально приходит слева, исходящий справа.
- После остановки трафика полоса плавно гаснет, затем появляется «Ожидание трафика».
- С выключенными анимациями полоса статична и не держит цикл анимации.
