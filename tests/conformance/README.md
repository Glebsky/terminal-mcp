# Conformance: verify the observable MCP API

Run on Windows with project dependencies installed. No tunnel, provider account, API secret, packaged Electron app, or Rust installation is required. These tests must **not** target a live MCP installation.

- `npm run test:conformance`: from source, builds the TS server and starts isolated children. They bind loopback on free ports, use scratch roots, random keys, `FULL_ACCESS=false`, all tools enabled with standard limits, and no tunnels. No production `.env` is loaded. Each functional scenario owns and cleans only its test directory. The suite checks Streamable HTTP, legacy SSE, auth and Host policy, files and scope, fixed PowerShell results and the 1 second timeout / 3 second return bound. Windows PowerShell is required for the three fixed terminal checks.
- Set `CONFORMANCE_BROWSER=1` to also launch a new headless Chrome/Edge against a loopback HTML fixture; do not attach a real browser or reuse a logged-in profile. Browser binaries are optional in normal CI.
- `npm run contract:dump`: explicitly redraws `contracts/tools.json` from a new isolated server, **not** from `MCP_URL`. Review the diff before committing it. Ordinary tests read but never update the reference. Name ordering and object key ordering are deterministic; schema array order is preserved. Compare the projected `name`, `title`, `description`, `inputSchema` and `annotations` fields across all pages.
- `npm run test:desktop-control`: a separate main-process adapter check, independent of any MCP endpoint or screen.

## A separately launched server (including a future Rust build)

Use a disposable **local** server on its own explicit port. Give it a fresh key, bearer auth, default tool limits, all tools enabled, no tunnels, and `FULL_ACCESS=false`. Set `FILES_ROOT` **and the initial working directory of MCP operations** to an empty directory named `mcp-conf-<unique>` directly inside the OS temp directory; the only intended user of this instance is the test runner. Do not set an audit path or expose the endpoint. Set `MCP_URL` to its loopback `/mcp` URL and `MCP_KEY` to that test key **in the runner's environment**, then run `npm run test:conformance`. The URL and key must be supplied together. The command does not build or start the TS server in this mode. The owner stops the server and removes its empty root afterwards.

Why this guard: stateless MCP shares its working directory across requests. Before state-changing tests the runner checks the canonical scratch root and round-trips a fresh marker file. It writes unique case directories, restores the initial cwd, and refuses roots outside temp. `MCP_KEY` is never printed. Redirects and cross-origin continuation endpoints are not permitted. In external mode the process-stdio tests, the opt-in query-auth configuration test and the optional browser launch are intentionally skipped: they require ownership of the child or its configuration. SSE and HTTP still use the supplied server. The finite Streamable HTTP client deliberately does not subscribe to optional server-initiated notifications via a persistent `GET /mcp`. All RPC requests and results are real; the legacy streaming path uses a genuine `GET /sse` and `POST /messages`. A child-process check requires the SDK client to exit naturally while the server remains up.

## CI

Windows CI uses Node 24 and read-only repository permissions. It runs type checking, builds, conformance, desktop pipe and legacy IPC tests and checks for accidentally tracked secrets/builds by filename. Real provider circuits, packaging, Dependabot merges, signing, publishing and deployment are not part of this run. `test:tunnels` and the race audit are intentionally separate until their behaviour is reliably independent of the network.
